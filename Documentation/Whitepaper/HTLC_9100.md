# HTLC spending rule · height 9100

## Scope

From height 9100, SUMUWW permits the exact P2WSH SHA256/preimage/CLTV template below. This transaction-spending extension is independent of the asynchronous connection-proof rule activated at 9000. Ordinary P2WPKH transfers, existing valid outputs, coinbase maturity and value-conservation rules remain applicable. This is a fixed supported template, not a general-purpose script virtual machine or an automatic cross-chain exchange service.

## Supported template

```text
IF
    SHA256 <32-byte hash> EQUALVERIFY
    <receiver compressed public key> CHECKSIG
ELSE
    <refund height> CHECKLOCKTIMEVERIFY DROP
    <refund compressed public key> CHECKSIG
ENDIF
```

The redeem path requires a 32-byte preimage matching the committed SHA256 hash and the receiver's valid signature. The refund path requires the specified block-height condition and the refund key's valid signature. Only canonical compressed public keys, exact pushes and SIGHASH_ALL are accepted. Refund locktime is enforced with transaction finality and a nonfinal input sequence. General scripts and CSV are outside this template.

## Independent validation

Each spending input is checked against the locally validated UTXO and current block context. A peer's claim that payment or refund completed does not replace verification of the transaction and chain. A chain reorganization can affect confirmations; the connection-proof system does not give this template irreversible finality.
