## 2026-10-19 · v4 · 9000 · 10%

9000번부터 10% 확률로 선택된 블록에만 BLS 증명과 분할 흔적을 적용합니다. 흔적은 중간 일반 PoW 블록을 건너 다음 선택 블록으로 이어집니다. 필수 증명 누락·등록 이력 충돌은 거부하며, 정상 공통 기록의 코인을 쓰는 거래는 계속 검증·처리합니다.

## 목적과 범위

SUMUWW는 자체 제네시스 블록, 거래 이력, 네트워크와 미사용 거래 출력(UTXO) 집합을 갖는 독립 코인이다. SHA-256d 작업증명, UTXO 기반 장부, secp256k1 소유자 서명 검증, 노드의 독립적인 블록·거래 검증, 유효한 누적 작업량에 따른 체인 선택을 구현한다.

발행 일정, 제네시스, 주소, 통신 식별자와 지원 거래 형식은 이 백서와 프로토콜 명세에서 정의한다.

## 발행

첫 150,000개 블록의 발행 보상은 블록당 50 SMW다. 이후 블록당 25 SMW에서 시작해 210,000블록마다 절반으로 줄이며, 최소 단위 미만은 버린다.

| 블록 높이 | 블록당 발행 보상 |
|---|---:|
| 0–149,999 | 50 SMW |
| 150,000–359,999 | 25 SMW |
| 360,000–569,999 | 12.5 SMW |
| 570,000–779,999 | 6.25 SMW |
| 780,000–989,999 | 3.125 SMW |
| 6,660,000–6,869,999 | 0.00000001 SMW |
| H ≥ 6,870,000 | 0 SMW |

```text
0 <= H < 150000: S(H) = 5000000000
H >= 150000:
    k = floor((H - 150000) / 210000)
    if k >= 32: S(H) = 0
    otherwise: S(H) = floor(2500000000 / 2^k)
```

명목 최대발행량: **17,999,999.97690000 SMW**.
사용 불가능한 제네시스 보상 제외 최대량: **17,999,949.97690000 SMW**.

유효한 블록의 코인베이스 거래는 해당 높이의 발행 보상과 블록에 포함된 거래의 수수료를 합한 금액까지 지급할 수 있다. 노드는 이 한도를 초과한 보상을 거부한다. 수수료는 기존 코인의 이전이며 추가 발행이 아니다. 발행 규칙에 개발자 전용 할당은 없고, 관리자에게 임의 발행·동결·몰수·잔액 수정 권한을 부여하지 않는다. 채굴 보상은 소비 블록 높이와 생성 블록 높이의 차이가 100 이상일 때 사용할 수 있다.

## 작업증명·난이도·체인 선택

SHA-256d 작업증명과 유효한 블록 내용이 필요합니다. 목표 평균 블록 간격은 600초입니다. 높이 8,064 미만은 기존 2,016블록 주기 조정 규칙을 유지합니다. 높이 8,064부터 DGW v3가 같은 부모 분기의 직전 24개 블록을 사용해 매 블록 난이도를 다시 계산합니다. 실제 블록 생성 간격은 달라질 수 있습니다.

제네시스 해시는 `00000032e243a8c71b449b13c2da733dd329f308a75aa4358f3f22707a28af97`다. 채굴 후보를 만들 때는 부모 블록이 속한 분기에 필요한 nBits를 설정한다. 완성된 블록의 수용, 분기 검증, 저장된 체인의 재검증에서는 기대 nBits와 작업증명을 모두 확인한다.

노드는 먼저 거래와 블록의 유효성을 검사하고 유효 누적 작업량이 가장 큰 체인을 선택한다. 누적 작업량은 각 블록의 유효한 난이도 목표로 계산하며, 상대가 주장하는 채굴 속도나 작업량을 그대로 받아들이지 않는다. 더 큰 작업량의 유효 분기가 도착하면 거래 기록과 UTXO를 그 분기에 맞춰 재구성한다. 거래 확인 수가 줄거나 거래가 현재 체인에서 빠질 수 있다.

## 기록의 순서와 정상 분기

블록의 순서는 헤더가 가리키는 **부모 블록의 해시**로 정한다. 높이 101의 블록은 특정한 높이 100의 블록을 부모로 삼고, 높이 102의 블록은 특정한 높이 101의 블록을 부모로 삼는다. 컴퓨터 시계나 블록 시각만으로 기록 순서를 정하지 않는다. 블록 시각은 부모부터 최대 11개 조상 블록 시각의 중앙값보다 커야 한다. 수신 노드 시각보다 7,200초를 넘게 앞선 새 블록은 즉시 수용하지 않으며, 나중에 다시 검사할 수 있다. 난이도 조정에도 해당 분기의 블록 시각을 사용한다.

정상 채굴자 두 명이 같은 높이 100의 블록을 기준으로 각자 다음 블록을 계산하면, 서로 다른 **101A와 101B**를 만들 수 있다. 두 블록의 부모와 기대 난이도는 같아도 채굴 보상을 받을 주소·거래 묶음·nonce가 달라 블록 해시가 달라진다. 두 블록 모두 작업증명과 내용 검사를 통과하면 유효한 경쟁 분기다. 이 상황만으로 어느 채굴자가 규칙을 어겼다고 판단하지 않는다.

| 관측한 상태 | 해당 노드의 선택 |
|---|---|
| 101A를 먼저 수용하고 동일 누적 작업량의 101B를 받음 | 현재 활성 분기인 101A를 유지하고 101B도 유효한 가지로 저장 |
| 다른 노드가 101B를 먼저 수용함 | 그 노드는 동일 작업량 동안 101B를 유지할 수 있음 |
| 101B 뒤에 유효한 102B가 이어져 B의 누적 작업량이 더 커짐 | 102B까지의 분기를 활성 체인으로 선택 |

동일 작업량일 때 먼저 수용한 분기를 유지하는 기준은 **각 노드가 받은 순서**다. 세계 전체에서 가장 먼저 완성한 블록을 측정해 영구 승자로 정하는 규칙이 아니다. 이후 더 큰 유효 누적 작업량의 분기가 오면 선택은 바뀐다. 블록 높이가 같아도 분기마다 난이도가 달라지는 상황에서는 높이만 비교하지 않고 누적 작업량을 비교한다.

101A가 활성 체인에서 빠지면 그 블록의 채굴 보상은 현재 활성 UTXO 집합에 남지 않는다. 일반 거래도 새 체인을 기준으로 다시 확인한다. 새 체인에서 아직 유효한 거래는 mempool에 다시 들어갈 수 있고, 입력이 없어졌거나 이미 소비된 거래는 거부한다. 각 노드는 이러한 판단에 따라 자체 장부 상태의 일관성을 유지한다.

## 채굴 프로그램 개조와 유효성

같은 계산을 더 빠르게 수행해도 기대 난이도와 보상 규칙을 충족해야 한다. 작업증명 검사는 제출된 블록 해시가 정해진 목표를 만족하는지를 확인한다. 계산에 걸린 시간이나 사용한 장비·최적화 방법의 증명을 요구하지 않으므로, 더 빠른 유효 계산은 허용한다. 계산 속도가 빨라졌다는 이유로 요구되는 난이도를 임의로 낮추거나 추가 보상을 받을 수는 없다. 정상 최적화로 얻은 보상은 성숙 후 일반 지갑으로 송금할 수 있다.

임의로 낮춘 난이도, 초과 보상, 없는 입력이나 잘못된 서명을 정상 노드는 거부한다. 무효 블록의 출력은 정상 활성 장부에 생기지 않으므로 일반 지갑으로 옮긴다고 유효한 코인이 되지 않는다. 거래 서명은 기존 출력의 소유권을 증명하며, 무효 출력을 새로 유효하게 발행하는 권한을 주지 않는다.

규칙을 지킨 비공개 체인이 더 큰 누적 작업량을 확보하면 거래 기록이 바뀔 수 있다. 오프라인에서 생성했다는 이유만으로 블록이 무효가 되지는 않으며, 노드는 동일한 합의 규칙으로 유효성을 판단한다. 거래 확인 수는 취소 불가를 보장하지 않는다. 작업증명의 보안은 정직한 채굴 작업량과 노드의 독립 검증에 의존하며, 과반 해시레이트 공격에 대한 완전한 방어를 보장하지 않는다.

## 거래와 UTXO

장부는 아직 사용하지 않은 거래 출력인 UTXO를 기록한다. 거래는 기존 출력을 소비하고 새 출력을 만든다. 노드는 입력의 존재·중복·성숙 조건, 소유자 서명과 금액 합계를 검사해 이중 지출과 보유 금액을 초과하는 지출을 거부한다. 기본 지출 형식은 네이티브 P2WPKH와 `SIGHASH_ALL`이다.

## 거래 확인 수와 채굴 보상 성숙

거래 확인 수는 거래가 현재 활성 체인의 블록에 포함된 깊이다. 거래가 높이 101의 블록에 처음 포함되고 현재 체인 끝도 높이 101이면 1회, 높이 102까지 이어지면 2회다. 아직 블록에 포함되지 않은 거래는 대기 상태이며 확인 수는 0이다. 체인 전환으로 포함 블록이 빠지면 이 수치와 대기 여부를 새 체인에 맞춰 다시 계산한다.

채굴 보상의 **100블록 성숙 규칙**은 일반 송금의 확인 수와 목적·적용 대상이 다르다.

| 대상 | 사용할 수 있는 조건 |
|---|---|
| 코인베이스 출력(블록 보상) | 소비 블록 높이 − 생성 블록 높이가 100 이상 |
| 일반 거래로 받은 출력 | 유효한 UTXO 집합에 존재하거나 같은 블록에서 앞서 처리된 유효 거래가 생성한 출력이며, 아직 소비되지 않았고 지출 조건을 만족 |

높이 1에서 얻은 채굴 보상은 높이 101의 블록에서 처음 소비할 수 있다. 한 채굴자가 혼자 101개 블록을 만들 필요는 없고, 여러 채굴자가 이어 만든 같은 활성 체인의 높이를 사용한다.

성숙한 보상을 일반 거래로 다른 지갑에 보냈다고 수신자가 다시 100블록을 기다리게 되지는 않는다. 예를 들어 높이 101의 일반 거래에서 생성된 출력은 지출 조건을 충족하면 같은 블록의 후속 거래 또는 높이 102 이후의 블록에 포함되는 거래에서 사용할 수 있다.

## 노드와 데이터 검증

각 노드는 자체 데이터베이스에 블록과 UTXO를 저장하고 수신한 데이터를 독립적으로 검증한다. 노드끼리는 IPv4 또는 IPv6 TCP로 블록과 거래를 전달한다. 연결이 복구되면 누락된 기록을 받아 검증하고, 유효 누적 작업량이 가장 큰 분기를 선택한다. 작업량이 같은 분기 사이에서는 각 노드가 현재 분기를 유지하며, 작업량이 엄격히 더 큰 유효 분기가 나타나면 전환한다.

## 수수료와 합의 규칙의 변경

수수료는 입력 합계에서 출력 합계를 뺀 금액이다. 보내는 사람이 송금액에 수수료를 더해 부담하며, 받는 사람은 지정한 송금액 전부를 받는다. 해당 거래를 포함한 블록의 채굴자는 발행 보상과 수수료를 받을 수 있다. 개발자 몫, 자동 소각, 추가 발행은 없다. 혼잡할 때 높은 수수료는 거래가 블록에 포함될 가능성에 영향을 줄 수 있지만, 목표 블록 간격을 바꾸거나 빠른 전파·확인을 보장하지는 않는다.

각 노드는 계속 독립 검증하고 제작자나 API 호출자에게 강제 업데이트·임의 발행·동결·잔액 수정 권한을 주지 않는다. 합의 규칙 변경의 채택은 자발적이며 체인이 갈라질 수 있다. 다른 사람이 포크를 만드는 것을 암호학적으로 금지하는 장치는 아니다. SUMUWW는 탈중앙 합의 구조를 갖는다. 실제 탈중앙화는 독립적인 노드 운영자와 채굴자의 지속적인 참여에 달려 있다.

## 참여와 개인정보

누구나 SUMUWW 풀노드를 운영하고 같은 합의 규칙에 따라 장부를 검증하거나 채굴에 참여할 수 있다. 중앙 관리자의 참여 승인은 필요하지 않다.

P2P 상대 노드는 연결 IP 주소를 볼 수 있다. 프로토콜은 참여자의 익명성을 보장하지 않는다.

## 최신 소스 규칙: 9000번부터 무작위 서명 블록

이 문서는 Windows 0.57.25·Android 0.6.75를 바탕으로 한 2026-10-19 무작위 10% 수정 소스를 설명합니다. 기존 설치 파일은 매 블록 서명 규칙을 담고 있습니다. 사용자의 PC·실제 휴대폰에 이 수정본을 설치하거나 공개 배포하지 않았습니다. 별도 검사 APK는 격리 에뮬레이터에서만 사용합니다.

9000번부터 각 부모·높이 문맥에서 다음 블록의 BLS 서명 필요 여부를 10% 확률로 결정합니다. 입력은 `sumuww-random-boundary-block-10pct-v1` 구분값과 네트워크 식별값·해당 높이·직전 블록 해시입니다. 현재 후보의 nonce와 거래는 입력에서 제외합니다. 10%는 평균 확률이며 고정된 10블록 간격이나 준비 완료 시한이 아닙니다. 채굴자의 난수 편향 가능성까지 제거했다고 입증한 규칙도 아닙니다.

선택된 블록만 완성된 증명서를 요구합니다. 최초 선택 블록의 `start`는 `null`이며, 이후 선택 블록은 가장 가까운 이전 선택 블록과 연결됩니다. 중간 일반 PoW 블록에는 증명서와 분할 흔적이 없습니다. 일반 블록도 원래 PoW·거래·내용 검사와 등록 이력 충돌 검사를 통과해야 합니다. 서명 점수를 작업량에 더하지 않습니다.

선정 팀은 서로 다른 식별값 3개와 관찰된 서로 다른 IP 3개를 가진 세 노드입니다. 요청·응답은 간접 연결 노드에도 중계됩니다. 응답자 1024개·이웃 관찰 32개 상한은 제거됐습니다. BLS 개인키는 실제 선정 노드의 키이며, 공개된 블록 선택 씨앗값으로 개인키를 만드는 방식이 아닙니다. 현재 채굴 서비스는 PoW 결과가 나온 뒤 최종 서명을 받고 그동안 다음 후보의 해시 작업을 병행합니다. 이 수정으로 서명 지연 없음이나 PoW 이전 전달 완료를 입증한 것은 아닙니다.

## 구버전의 송금과 분기 합류

| 최신 소스가 받는 자료 | 검사 결과 |
|---|---|
| 선택된 높이에서 구버전이 만든 서명 없는 블록 | 완성된 경계 증명이 없어 거부 |
| 선택되지 않은 높이에서 구버전이 만든 블록 | 원래 규칙과 등록된 조상 이력이 맞으면 수용 가능 |
| 이미 등록한 선택 블록과 충돌하는 더 긴 분기 | 등록 연결 충돌로 거부. 추가 작업량만으로 우회하지 못함 |
| 정상 공통 기록의 성숙·미사용 출력을 쓰는 구버전 지갑 거래 | 소유자 서명·금액 등을 검증하여 중계·확정 가능 |
| 거부된 분기에만 있는 채굴 보상을 쓰는 거래 | 미존재·기소비 입력으로 거부. 블록 증명과 지갑 서명은 별도 검사 |

프로그램이 오래됐다는 이유만으로 정상 기존 코인 전부를 막는 규칙은 없습니다. TCP 연결 성공과 활성화 이후 블록 호환성은 다릅니다. 상대 피어가 필수 증명서를 제공하지 못하면 그 선택 블록을 동기화할 수 없습니다.

기존 매 블록 규칙의 DB 표시는 활성화 높이 이상의 블록이 하나도 없고 증명·분할 연결·등록 테이블이 모두 비어 있을 때만 갱신합니다. 검증된 기존 블록·UTXO·지갑·잔액은 보존합니다. 이미 활성화 이후 기존 정책으로 기록된 DB는 몰래 재해석하지 않고 거부합니다.

## 조회·요청·연결·주소 정리

진행 중인 탐색 객체와 대기 Event는 조회 개수 때문에 삭제하지 않습니다. 사용자가 없는 이전 부모 조회와 유휴·완료·취소 조회를 정리합니다. 새 응답이 없는 로컬 탐색은 명시적인 유휴 오류로 종료하며, 일부 응답만으로 증명을 완성하거나 몰래 다시 추첨하지 않습니다.

서명·중계 요청 512개, 기본 직접 피어 연결 수, 발견 주소 128개·64KiB 상한은 없습니다. 실패 주소는 삭제하고 실제 정상 대체 연결은 보존합니다. 끝난 호출 기록과 만료된 재시도 억제 기록도 정리합니다. 유휴 보관 시간은 `max(60초, 소켓 timeout×8, 측정 처리 시간×2)`이며 전송·실행·대기 참조가 있는 작업은 보호합니다. 수동 저장한 접속 선호 설정은 발견 캐시와 별도입니다. 사용자가 CLI의 `--max-peers`를 명시하는 선택적 운영 설정은 남아 있으며 앱의 기본값에는 적용하지 않습니다.

큰 경계 자료는 인증된 `bpart`로 분할 전송합니다. 데이터 조각은 256KiB이며 전송 식별값·순서·전체 해시를 검사합니다. 증명 전체의 1MiB 상한은 제거됐습니다. `bblock`의 uint32 증명 길이와 일반 프레임·거래·블록 크기, DHT 라운드 예산, 피어별 통신량 할당은 별도 범위입니다. 검사에 사용한 수량은 새 개수 제한이 아닙니다.

## 실제 코드 검사와 범위

구버전 0.57.22 코어로 격리된 regtest 8999번까지 직접 채굴·검증하고 서명 없는 분기를 9111번까지 만들었습니다. 마지막 배포 정책은 9000번 블록을 거부했습니다. 최신 소스는 시험한 주 분기의 9000~9003번을 받고 선택 블록인 9004번에서 필수 증명 누락을 거부했습니다. 동일 블록에 세 실제 개인키의 BLS 증명을 붙이면 통과했습니다. 충돌 분기와 그 보상 거래는 거부되고, 정상 공통 기록의 구버전 거래는 접수·확정됐습니다. 실제 TCP 접속에서도 구버전이 증명을 제공하지 못하는 선택 블록을 거부했습니다. 선택 높이는 부모 해시에 따라 달라집니다.

이는 실제 숫자 높이에서 원래 코드를 실행한 격리 시험입니다. 공개망 전환, 전 세계 노드 전수 확인, 독립 운영자 증명, 51% 공격 전체 방어의 입증은 아닙니다. 원래 PoW·최초 블록·발행·소유자 서명·보상 성숙 규칙은 유지됩니다.
