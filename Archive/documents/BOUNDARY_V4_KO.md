# SUMUWW v4·9000번 경계 서명 규칙

기준 구현: Windows 0.57.25 / Android 0.6.75 기반 무작위 10% 수정 소스. 확인일: 2026-10-19. 실제 코드를 설명하며, 공개망 전환 완료나 독립 보안 감사를 뜻하지 않습니다.

## 활성화와 호환성

9000번부터 10% 확률로 선택된 블록에만 완성된 경계 증명과 분할 흔적을 적용합니다. 최초 선택 블록의 `start`는 `null`이며, 이후 선택 블록은 가장 가까운 이전 선택 블록과 연결됩니다. 일반 PoW 블록은 그 사이를 기존 블록 연결로 이어갑니다.

최초 블록, 기존 주소·소유권·UTXO, 보상과 수수료는 바뀌지 않습니다. 추가된 합의 검증 규칙이므로, 이를 검사하지 않는 이전 버전과는 9000번 이후 규칙이 다릅니다. 전환 전 연결 성공이 전환 후 호환성을 뜻하지 않습니다. 같은 체인을 이용할 참여자는 호환 버전이 필요합니다. 가상 시험에서 사용하는 별도 활성화 높이는 공개망 설정이 아닙니다.

## 작업증명과 서명

블록 식별값과 PoW는 기존 80바이트 헤더의 SHA-256d입니다. 경계 증명은 별도로 전달하며 자신이 서명하는 해시의 계산 원본에 다시 넣지 않습니다. 서명에는 실제 완성된 블록 해시, 네트워크, 부모 연결과 선정 응답 묶음이 연결됩니다. 거래나 nonce를 변경한 블록에 같은 증명서를 붙일 수 없습니다.

현재 채굴 서비스는 유효한 PoW를 찾은 뒤 선정자들의 최종 서명을 받고 검증한 다음 블록을 등록·전파합니다. 그 증명서가 완성되는 동안 작업 스레드는 아직 등록 전인 부모 후보 위에서 다음 후보의 해시 작업을 진행할 수 있습니다. 탐색이나 서명 때문에 기다릴 수 있습니다. 지연 없음·고정된 초 이하 완료·서명 없는 활성화 블록 허용은 구현된 기능이 아닙니다.

누적 작업량은 유효한 난이도에서 계산한 `floor(2^256 / (target + 1))`의 합입니다. 서명 점수를 작업량에 더하지 않습니다. 아래 경계 검증과 이미 등록된 연결 보호 조건을 통과한 후보 사이에서 누적 작업량을 비교합니다.

## 응답자·씨앗값·무작위 선정

서명된 요청·응답은 인증된 v4 연결을 통해 간접 연결 노드에도 중계됩니다. 저장된 주소나 과거 연결, 피어 숫자만으로 선정 자격이 생기지 않습니다. 응답에는 식별키, 요청, ECVRF 추첨값, 현재 이웃과 실제 소켓에서 관찰한 IP 정보가 연결됩니다.

추첨 입력에는 네트워크 식별값·부모 높이·부모 해시·자식 높이가 들어갑니다. ECVRF-EDWARDS25519-SHA512-TAI 증명을 검사하고, 응답 묶음 안의 추첨 출력과 식별값으로 결과를 재현합니다. **서로 다른 노드 식별값 3개와 관찰된 서로 다른 IP 3개**를 가진 한 팀을 고릅니다. 국가·지리적 지역·통신사·사람을 판별하지 않습니다. 같은 식별키의 주소가 여러 개여도 같은 팀에서 여러 명으로 늘어나지 않습니다.

응답 묶음은 서로 확인한 이웃 관계로 연결되어야 하며 IP 관찰값이 필요합니다. 응답자 수와 이웃 관찰 수의 고정 개수 상한은 제거됐습니다. 현재 탐색은 유효한 연결 응답 묶음이 생기면 반환합니다. **전 세계의 모든 실행 중 노드가 빠짐없이 포함됐음을 입증하는 기능은 구현되어 있지 않습니다.** IP 정보는 이웃의 서명된 관찰 보고이며, 검증자가 모든 외부 소켓을 다시 직접 확인하는 방식은 아닙니다.

## 무응답·사용 불가 응답의 교체

아직 서명하지 않은 선정자에게 서명을 요청합니다. 응답이 없거나 사용할 수 없으면 다른 응답자들의 현재 준비 응답을 받아, 서로 다른 IP 조건을 유지할 수 있는 대상 중 해당 자리만 무작위로 교체합니다. 이미 받은 정상 서명은 유지합니다. 나머지 두 선정자의 교체 승인이나 고정된 예비 순번은 없습니다.

대기 예산은 로컬 암호 연산 측정값과 응답 묶음 크기로 계산하며 전 세계 공통 제한시간이 아닙니다. 교체 기록에는 요청자·블록·응답 묶음·자리·교체 대상·보고된 사유가 서명됩니다. 수신자는 기록의 서명과 교체 계산을 검사합니다. 이것은 요청자의 보고를 인증하며 상대방이 전 세계적으로 응답하지 않았음을 별도로 증명하지 않습니다. 교체 가능한 응답자가 없으면 후보와 받은 서명을 유지하고 빠진 서명을 다시 요청합니다.

## 완성된 서명의 분할과 다음 경계

노드 식별 메시지는 Ed25519, 경계 서명은 소유 증명(PoP)이 있는 BLS12-381을 사용합니다. 서로 다른 세 공개키의 최종 서명을 96바이트 집계 서명 하나로 압축해 `AggregateVerify`로 검사합니다. 공동 개인키를 가진 2/3 임계서명 방식은 아닙니다.

다음 선택 블록과의 연결에는 **이미 완성된 집계 서명 S**를 BLS 군에서 나눕니다. 무작위 유효 점 A를 고르고 B = S − A로 정합니다. A와 B는 각각 96바이트이며, 올바른 부분군에 있고 A + B = S인지 부모 블록·증명서 해시와 함께 확인합니다. 별개의 서명 두 개, 개인키 분할, 미래 블록 해시 예측이 아니며 원본보다 총 저장량이 줄어드는 분할도 아닙니다.

블록 등록과 같은 DB 트랜잭션에서 A는 부모의 연결 말단 기록에, B는 자식 증명 기록에 저장합니다. 읽을 때 완성된 연결 증명을 재구성합니다. 이는 체인 DB의 별도 연결 기록입니다. 이미 채굴된 부모의 80바이트 헤더를 고치거나, 부모가 채굴되기 전에 A가 헤더에 들어 있었다는 시점 증명을 만들지 않습니다.

자식의 서명은 이 연결을 포함한 문맥을 대상으로 합니다. 자식의 완성된 집계 서명은 그다음 연결에 다시 분할할 수 있습니다. 수신 노드는 등록 전에 증명서·부모 연결·분할 복원·선정·교체 기록을 확인하며, 재시작할 때 저장된 연결도 재검사합니다.

## 등록된 이력과 보안 범위

활성화 이후 수신 노드는 받아들인 연결의 높이·해시·부모·증명서 식별값을 저장합니다. 이 노드가 이미 등록한 연결과 충돌하거나 이후 등록 이력을 잘라내는 후보는 더 큰 작업량을 주장하더라도 거부합니다. 서명 직전에도 후보를 재검사합니다. 별도의 영구 서명 잠금은 같은 네트워크·높이·부모 문맥의 다른 메시지에 중복 서명하는 것을 막습니다. 미완성 후보는 저장하여 중단 후 같은 후보로 이어갑니다.

이 검사는 해당 노드의 등록 이력을 보호합니다. 독립된 모든 노드의 최초 등록이 같았다는 사실까지 증명하지는 않습니다. 서로 다른 최초 등록을 전체망에서 하나로 정하는 별도 최종성 투표는 현재 코드에 없습니다. 다른 IP가 다른 운영자를 증명하지 않으며, 서명된 관찰로 가짜 다수 노드·통신 경로·망 분리 위험이 사라지는 것도 아닙니다. 따라서 51% 공격 전체를 완전히 차단한다는 보장은 성립했다고 확인하지 않았습니다.

## v4 통신

24바이트 프레임 헤더, 네트워크 magic·최초 블록·프로필 검사와 `version`/`verack`은 유지됩니다. 통신 버전 1·2·3·4를 인식합니다. 주소 교환은 v2 이상, IPv6 주소 힌트는 v3 이상이며 v4도 포함합니다. 경계 기능이 켜진 런타임은 우선 v4를 시도하고 이전 피어를 위한 호환 재시도 경로를 갖습니다.

| 명령 | 역할 |
|---|---|
| `bhello` | 현재 연결에서 교환한 nonce·네트워크와 노드 식별키·BLS 참여 정보를 서명으로 연결 |
| `bquery` | 부모 문맥에 대한 서명된 탐색 요청 중계 |
| `bresponse` | 요청에 연결된 서명 응답 중계 |
| `bcall` | 인증된 `ready`·`sign` 요청과 회신 중계 |
| `bpart` | Authenticated multipart transfer / 큰 경계 자료 분할 전송 |
| `bblock` | 원래 블록과 완성된 경계 증명 전달 |

경계 명령은 인증된 v4 연결을 요구합니다. 큰 자료는 256KiB 데이터 조각의 `bpart`로 나눠 전송하며 전송 식별값·순서·전체 해시를 검사합니다. 전체 증명의 1MiB 상한은 제거됐습니다. `bblock`은 `uint32_le 증명길이 || 정규 JSON 증명 || 원래 블록 바이트`입니다. 일반 프레임·거래·블록 크기와 피어별 통신량 할당은 별도입니다.

## 구현 위치와 운영 확인

구현은 `sumuww/boundary.py`, `boundary_crypto.py`, `boundary_runtime.py`, `boundary_state.py`, `chain.py`, `app_service.py`, `peer.py`, `wire.py`에 있습니다. Android에도 같은 합의 모듈이 포함됩니다. 경계 서명용 노드 키는 지갑 소유 키와 별개이며, 서명 이력의 연속성을 위해 노드 상태와 함께 보존해야 합니다. 이 개인키를 포함한 백업은 비공개로 보관해야 합니다.

설치 버전·공개 프로필·활성화 높이·실제 인증 연결·경계 오류를 확인해야 합니다. 피어 연결은 상대방의 채굴을 증명하지 않습니다. 저장 주소·탐색 응답과 블록 등록·작업량·증명서 검증은 서로 다른 값입니다. 프로젝트의 가상 시험과 기기 화면 검사는 공개망 전체의 채택이나 활성화 완료를 증명하지 않습니다.


## 최신 소스 규칙: 9000번부터 무작위 서명 블록

이 문서는 Windows 0.57.25·Android 0.6.75를 바탕으로 한 2026-10-19 무작위 10% 수정 소스를 설명합니다. 기존 설치 파일은 매 블록 서명 규칙을 담고 있습니다. 사용자의 PC·실제 휴대폰에 이 수정본을 설치하거나 공개 배포하지 않았습니다. 별도 검사 APK는 격리 에뮬레이터에서만 사용합니다.

9000번부터 각 부모·높이 문맥에서 다음 블록의 BLS 서명 필요 여부를 10% 확률로 결정합니다. 입력은 `sumuww-random-boundary-block-10pct-v1` 구분값과 네트워크 식별값·해당 높이·직전 블록 해시입니다. 현재 후보의 nonce와 거래는 입력에서 제외합니다. 10%는 평균 확률이며 고정된 10블록 간격이나 준비 완료 시한이 아닙니다. 채굴자의 난수 편향 가능성까지 제거했다고 입증한 규칙도 아닙니다.

선택된 블록만 완성된 증명서를 요구합니다. 최초 선택 블록의 `start`는 `null`이며, 이후 선택 블록은 가장 가까운 이전 선택 블록과 연결됩니다. 중간 일반 PoW 블록에는 증명서와 분할 흔적이 없습니다. 일반 블록도 원래 PoW·거래·내용 검사와 등록 이력 충돌 검사를 통과해야 합니다. 서명 점수를 작업량에 더하지 않습니다.

선정 팀은 서로 다른 식별값 3개와 관찰된 서로 다른 IP 3개를 가진 세 노드입니다. 요청·응답은 간접 연결 노드에도 중계됩니다. 응답자 1024개·이웃 관찰 32개 상한은 제거됐습니다. BLS 개인키는 실제 선정 노드의 키이며, 공개된 블록 선택 씨앗값으로 개인키를 만드는 방식이 아닙니다. 현재 채굴 서비스는 PoW 결과가 나온 뒤 최종 서명을 받고 그동안 다음 후보의 해시 작업을 병행합니다. 이 수정으로 서명 지연 없음이나 PoW 이전 전달 완료를 입증한 것은 아닙니다.

## 구버전의 송금과 분기 합류

| 최신 소스가 받는 자료 | 검사 결과 |
|---|---|
| 선택된 높이에서 구버전이 만든 서명 없는 블록 | 완성된 경계 증명이 없어 거부 |
| 선택되지 않은 높이에서 구버전이 만든 블록 | 원래 규칙과 등록된 조상 이력이 맞으면 수용 가능 |
| 이미 등록한 선택 블록과 충돌하는 더 긴 분기 | 등록 연결 충돌로 거부. 추가 작업량만으로 우회하지 못함 |
| 정상 공통 기록의 성숙·미사용 출력을 쓰는 구버전 지갑 거래 | 소유자 서명·금액 등을 검증하여 중계·확정 가능 |
| 거부된 분기에만 있는 채굴 보상을 쓰는 거래 | 미존재·기소비 입력으로 거부. 블록 증명과 지갑 서명은 별도 검사 |

프로그램이 오래됐다는 이유만으로 정상 기존 코인 전부를 막는 규칙은 없습니다. TCP 연결 성공과 활성화 이후 블록 호환성은 다릅니다. 상대 피어가 필수 증명서를 제공하지 못하면 그 선택 블록을 동기화할 수 없습니다.

기존 매 블록 규칙의 DB 표시는 활성화 높이 이상의 블록이 하나도 없고 증명·분할 연결·등록 테이블이 모두 비어 있을 때만 갱신합니다. 검증된 기존 블록·UTXO·지갑·잔액은 보존합니다. 이미 활성화 이후 기존 정책으로 기록된 DB는 몰래 재해석하지 않고 거부합니다.

## 조회·요청·연결·주소 정리

진행 중인 탐색 객체와 대기 Event는 조회 개수 때문에 삭제하지 않습니다. 사용자가 없는 이전 부모 조회와 유휴·완료·취소 조회를 정리합니다. 새 응답이 없는 로컬 탐색은 명시적인 유휴 오류로 종료하며, 일부 응답만으로 증명을 완성하거나 몰래 다시 추첨하지 않습니다.

서명·중계 요청 512개, 기본 직접 피어 연결 수, 발견 주소 128개·64KiB 상한은 없습니다. 실패 주소는 삭제하고 실제 정상 대체 연결은 보존합니다. 끝난 호출 기록과 만료된 재시도 억제 기록도 정리합니다. 유휴 보관 시간은 `max(60초, 소켓 timeout×8, 측정 처리 시간×2)`이며 전송·실행·대기 참조가 있는 작업은 보호합니다. 수동 저장한 접속 선호 설정은 발견 캐시와 별도입니다. 사용자가 CLI의 `--max-peers`를 명시하는 선택적 운영 설정은 남아 있으며 앱의 기본값에는 적용하지 않습니다.

큰 경계 자료는 인증된 `bpart`로 분할 전송합니다. 데이터 조각은 256KiB이며 전송 식별값·순서·전체 해시를 검사합니다. 증명 전체의 1MiB 상한은 제거됐습니다. `bblock`의 uint32 증명 길이와 일반 프레임·거래·블록 크기, DHT 라운드 예산, 피어별 통신량 할당은 별도 범위입니다. 검사에 사용한 수량은 새 개수 제한이 아닙니다.

## 실제 코드 검사와 범위

구버전 0.57.22 코어로 격리된 regtest 8999번까지 직접 채굴·검증하고 서명 없는 분기를 9111번까지 만들었습니다. 마지막 배포 정책은 9000번 블록을 거부했습니다. 최신 소스는 시험한 주 분기의 9000~9003번을 받고 선택 블록인 9004번에서 필수 증명 누락을 거부했습니다. 동일 블록에 세 실제 개인키의 BLS 증명을 붙이면 통과했습니다. 충돌 분기와 그 보상 거래는 거부되고, 정상 공통 기록의 구버전 거래는 접수·확정됐습니다. 실제 TCP 접속에서도 구버전이 증명을 제공하지 못하는 선택 블록을 거부했습니다. 선택 높이는 부모 해시에 따라 달라집니다.

이는 실제 숫자 높이에서 원래 코드를 실행한 격리 시험입니다. 공개망 전환, 전 세계 노드 전수 확인, 독립 운영자 증명, 51% 공격 전체 방어의 입증은 아닙니다. 원래 PoW·최초 블록·발행·소유자 서명·보상 성숙 규칙은 유지됩니다.
